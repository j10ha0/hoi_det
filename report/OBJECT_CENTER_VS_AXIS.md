# 简化：只对准「物体中心」，不算物体法向量

> 你的想法：**"为什么要算物体的法向量？手向量只要对准物体中心就好了，我只需要检测物体中心"**
>
> **结论：对。这是更简单、更鲁棒的方案；PCA/主轴是过度设计。**

---

## 一、为什么"对准中心"就够了

### 对准的数学定义

```python
u = normalize(p_obj − p_palm)          # 从掌心指向物体中心
n = 掌心法向                             # 由手部姿态给出
对准 ⟺ angle(n, u) < ε
```

**对 1 自由度腕旋（旋前/旋后）来说，"掌心应该指向哪"这个目标——**
**物体中心就完全决定了**，不需要物体的朝向。

### 三个理由

| # | 理由 |
|---|------|
| 1 | **1-DOF 腕旋只能改变"掌心朝向"** —— 而"掌心朝向"的目标就是"对着物体"，中心点已给出这个方向 |
| 2 | **中心点比"掩膜形状"稳定得多** ⭐ —— 我们刚实测：PCA 对掩膜完整性极其敏感（部分掩膜直接毁掉主轴），而中心点几乎不受影响 |
| 3 | **闭环控制不需要精确目标** —— 视觉伺服只要误差单调可减就能收敛，用中心做目标误差信号平滑无跳变 |

---

## 二、⭐ 实测支持：PCA 是脆弱环节，中心点不是

前一轮 EgoTactile 批量测试的结果：

| 环节 | 失败数 | 原因 |
|------|--------|------|
| **手部检测（WiLoR）** | 2/30 | 手太小/姿态特殊 |
| **物体定位** | 0/30（绿幕法）| — |
| **物体主轴（PCA）** | **6/27 判错** | ⚠️ **掩膜不完整 / 前臂污染** |

**→ 失败几乎全在"物体主轴"这一步**，而不是"物体中心"。

**如果只对准中心，整条链路少一个脆弱环节。**

## 三、简化后的完整方案

```
① 手部          → WiLoR / MediaPipe
                   得到：掌心位置 p_palm + 掌心法向 n + 手的长轴 f
② 物体中心      → 检测框中心（YOLO） 或 掩膜质心（SAM/FastSAM）
                   得到：p_obj
③ 目标方向      → u = normalize(p_obj − p_palm)
④ 需转角度      → 把 n、u 投到垂直于 f 的平面
                   θ = atan2( dot(cross(n⊥, u⊥), f), dot(n⊥, u⊥) )
                   sign(θ) = 往哪转；|θ| = 转多少
⑤ 残余误差      → resid = arccos(n·u) − |θ|
                   ↑ 单自由度腕旋做不到的部分（物体在手的上/下方）
```

**删掉的东西**：PCA、主轴、特征值比、形状分类（"球/细长"那套）
**保留的东西**：手部检测、物体中心、几何投影

## 四、但有两个例外（什么时候还需要物体朝向）

| 场景 | 为什么中心不够 | 处理建议 |
|------|--------------|---------|
| **细长物体从"端面方向"接近** | 掌心指向中心 = 指向轴的方向 → 会去抓端面，而不是侧面力量抓 | 少见；可以**用抓握类型**处理（H2 头），而不是靠对准 |
| **带柄物体（要抓柄）** | 柄 ≠ 主体中心 | 这是**"抓握点检测"问题**，不是"对准"问题 → 单独用点检测解决 |

**→ 这两个都不是"对准"该解决的问题**，所以**不必为此保留 PCA**。

---

## 五、还有两个附带好处

### ① 残余误差本身是有用信号
```
resid 小  → 只转腕就能对准 ✓
resid 大  → 物体在手的"上/下方"，光转腕对不上 → 需要移动手臂/换姿态
```
**这是"用中心做目标"才能自然得到的控制信息。**

### ② 对分割质量的要求大幅下降
- 要**掩膜形状**（PCA）→ 必须分割完整，否则主轴错
- 只要**质心**（中心）→ 部分掩膜也能给出合理质心
- **→ 采集/部署的分割压力显著降低**

## 六、修正后的整体架构（更简洁）

```
┌─ 视觉 ──────────────────────────────────────────┐
│ ① 手:  WiLoR → 掌心位置 + 掌心法向 + 手的长轴     │
│ ② 物:  检测器 → 物体中心（框中心/质心）           │
│ ③ 几何: 对准误差 θ（绕手长轴）+ 残余误差          │
└─────────────────────────────────────────────────┘
        ↓
   控制器: ω = kp·θ ，|θ|<ε 持续 N 帧 → 对准完成
        ↓
   if resid 大 → 提示"需要移动手臂"（而不是硬转腕）

┌─ 抓握类型（H2，独立头）────────────────────────┐
│ 物体 shape（分类器）→ 抓握类型                  │
│ ⚠️ 注意：这是"抓什么"，不是"怎么对准"            │
└─────────────────────────────────────────────────┘
```

**关键区分**：
| 问题 | 用什么 |
|------|--------|
| **怎么对准？** | ⭐ **物体中心** + 掌心法向（几何）|
| **抓什么？** | 物体 shape 分类 → 抓握类型（学习）|
| 对不准怎么办？ | 残余误差大 → 移动手臂 |

**→ "物体形状"用于选抓握类型，不用于对准。两者解耦。**

---

## 七、一句话回答你

> **你说得对**：**对准只需要物体中心**，不需要物体法向量/主轴。
> `u = normalize(p_obj − p_palm)`，把掌心法向 n 转到 u 即可。
>
> **PCA/主轴是过度设计** —— 而且我实测发现它恰好是最脆弱的环节（对掩膜完整性敏感，前臂污染、部分掩膜都会毁掉主轴）。
>
> **删掉它后**：链路少一个失败模式、对分割质量要求更低、还能自然得到"残余误差"这个有用的控制信号（大 = 光转腕对不上，要移动手臂）。
>
> **物体形状仍然有用，但用途变了**：不是用来对准，而是用来**选抓握类型**（H2）—— 两者解耦。
