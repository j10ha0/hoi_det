# 流水线审计：这是蒸馏模型吗？PocketVLA 的思路走到哪了？

> 回答三个问题：
> ① 现在的模型是蒸馏后的小模型吗？
> ② PocketVLA 的思路（vision + 融合 trunk + action head + 辅助头）实现了多少？
> ③ 整条 pipeline 是 OK 的吗？

---

## 一、「是蒸馏模型吗？」—— **是，但只做了一半**

### 1.1 实测数字（刚补测，之前一直没测）

| | 参数量 | 延迟（batch=1, 224×224）| FPS | 显存 |
|---|--------|------------------------|-----|------|
| **教师 EgoHOS** | Swin-B + UPerHead ×**3 个模型** | **196.1 ms** | **5.1** | 1.71 GB |
| **学生（当前最佳）** | **23.61 M**（1 个模型）| **5.43 ms** | **184** | 0.24 GB |
| **加速** | — | **36.1×** | **36×** | 7× |

> FP16 无增益（5.69 ms，0.95×）—— batch=1 时开销主导，模型本身已很小。

**结论**：延迟目标（<33 ms/frame）**轻松满足**（5.4 ms），在线推理不是瓶颈。

### 1.2 但"蒸馏"只做了 2/3

| 蒸馏类型 | 说明 | 状态 |
|---------|------|------|
| **① 硬标签蒸馏**（伪标签 / data distillation）| 教师生成标签 → 学生学 | ✅ **做了**（且是主导信号）|
| **② 特征蒸馏**（hidden-layer KD）| 学生投影 → 与 Swin-B stage4 余弦对齐 | ✅ **做了**（λ=0.5，+3.8 点）|
| **③ 软标签蒸馏**（Hinton soft-logit KD）| 对教师 **9 类 logits** 做带温度的 KL | ❌ **没做** |

**③ 为什么重要**：软标签携带"暗知识"（边界模糊、1 级/2 级物体混淆、接触区不确定），
在小数据（863 帧）下往往比硬标签更有效 —— 这是我们**最该补的一块**。

### 1.3 一个被忽略的差异

学生的输出**已经不是教师的输出**：

| | 教师 EgoHOS | 学生 |
|--|-------------|------|
| 模型数 | 3 个（twohands / cb / obj1）| **1 个** |
| 类别 | 9 类（手×2、1/2 级物体×3、接触）| 手 3 类 + 接触 1 + 物体 1 |
| 语义 | 1 级/2 级交互物体 | **物体二值（丢了层级）** |

→ 这是**任务压缩式蒸馏**（不仅是同任务蒸馏）。好处是更快更简，代价是丢了 EgoHOS 的细粒度层级信息。

## 二、PocketVLA 思路的映射 —— **融合与控制那一半还没建**

PocketVLA（3M VLA）= vision encoder + language trunk + action head，
核心是 **token 级早期融合**（视觉/语言/本体/**action-query** 拼接过共享主干）+ **辅助头深度监督**。

| PocketVLA 组件 | 我们的现状 | 说明 |
|----------------|-----------|------|
| vision encoder | ✅ **ViT-Small**（从 EgoHOS 蒸馏）| 已做 |
| **辅助头（深度监督）** | ✅ 接触头 + 物体头 | 已做，且**验证了"容量够才有用"**（Tiny −2.0 / Small +5.3）|
| 类别平衡损失 | ✅ contact/object 用 pixel `pos_weight` + Dice | 已做 |
| **共享融合 trunk**（token 级双向注意力）| ❌ **未实现** | 缺 |
| **EMG tokens**（替代 language tokens）| ❌ **未实现** | 缺（你的核心创新点）|
| proprioception token | ❌ | 缺 |
| **action-query token** | ❌ | 缺 |
| **action head**（抓握控制）| ❌ | 缺 |
| SFT 行为克隆 | ❌ | 缺（还没有"动作"标签）|
| GRPO 强化学习 | ❌ | 缺（第二阶段）|

**一句话**：我们做完了 **PocketVLA 架构的"视觉前端 + 辅助头"**，
**"EMG token 融合 + action-query + 控制头"完全没开始** —— 而这恰恰是你要的创新点（V-E-A）。

## 三、整条 pipeline 是 OK 的吗？—— **技术上半条 OK，科学上有三个硬伤**

### 3.1 已完成且可靠的部分 ✅

```
EgoHOS 离线标注 → 伪标签数据集 → 学生训练（辅助头 + 特征蒸馏）→ 消融实验 → 36× 加速
```
- 全链路**可运行、可复现**，有 `report/` 统一记录（数字 → 脚本 → 日志）
- 关键发现经得起检验：**容量决定辅助头是否有用**；**λ 与教师层选择决定蒸馏成败**
- 延迟 5.4 ms，**在线可行**

### 3.2 三个硬伤 ⚠️

#### 硬伤 ①：**没有真值 → 评测是"自证"（循环论证）**
- 所有标签都来自 EgoHOS，我们用 student 去拟合 EgoHOS，再用"与 EgoHOS 的一致度"当指标
- 后果：**如果教师错了，学生学会它的错，我们还"验证"了它是对的**
- 现在的 hand F1 0.78 **≠ 真实分割精度**，只是"对教师的拟合度"
- 同理：**我们从未测过教师自己在这份数据上的精度**（因为也没真值）

**必须先解决**：人工标注一小份（如 100–200 帧）作为独立测试集。

#### 硬伤 ②：**主任务选错了（与目标不匹配）**
- 现在主任务是**手分割**，但你要做在线控制，真正需要的是 **接触状态 + 物体形状**
- 手掩膜只是"手段"，不是"目的"
- 证据：刚测出**左手 IoU 仅 0.145**（召回 0.146）→ 花了大力气优化的"手分割"里，有一半（左手）基本是坏的
- 而**接触/物体**这两个真正有用的头，F1 只有 0.18–0.34，且被当成"辅助"

**建议**：把任务重排为 ——
```
主任务：接触（二值）+ 物体形状（5 类）
辅助  ：手分割（或直接用 MediaPipe，根本不用学）
```

#### 硬伤 ③：**数据量与分布（根本瓶颈）**
- 只有 **2 段视频 / 863 帧**（训练 543）
- 训练视频与验证视频**场景不同**（左手占比 0.305 vs 0.724）→ 分布偏移
- 伪标签有噪声（EgoHOS 仅 36.4% 帧检出物体）

### 3.3 还有一个方法论问题

**多种子没做**：EXP_005 的 λ 排序（0.7832 vs 0.7729）**可能全在噪声内**。
在这种小数据上，**不跑多个 seed 的排名结论不可信**。

## 四、所以，接下来该做什么（按优先级重排）

| 优先级 | 任务 | 理由 | 时间 |
|--------|------|------|------|
| **P0** | **人工标注 100–200 帧真值测试集** | 打破循环论证；否则前面所有结论都无法对外说 | 半天 |
| **P0** | **任务重排**：接触+物体做主任务，手为辅助 | 对齐你的真实目标 | 1 次训练 |
| **P1** | **补软标签蒸馏**（对教师 9 类 logits 做 KL）| 小数据下最可能带来真实提升 | 1 天 |
| **P1** | **多种子**（3 seed × 3 配置）| 让 λ 结论站得住 | 40 分钟 |
| **P2** | **建 V-E-A 融合**：EMG tokens + action-query + 融合 trunk + action head | 你的创新点本体 | 1–2 周 |
| **P3** | **多速率在线推理框架** | 落地（EMG 30Hz / 视觉 10Hz）| 2–3 天 |
| **P3** | 采集自己的数据（多被试）| 根本解法 | 依赖采集 |

## 五、一句话回答你

> **① 是蒸馏模型，但只做了「硬标签 + 单层特征」两件事，缺软标签蒸馏；实测 5.43 ms / 184 FPS，比教师快 36×。**
> **② PocketVLA 的思路我们只实现了「vision encoder + 辅助头」，而「EMG token 融合 + action-query + 控制头」这一半（也是你的创新点）完全没建。**
> **③ 技术上管线跑通了、可复现、延迟达标；但科学上有三个硬伤：没有真值（循环论证）、主任务选错（手分割≠你要的接触/物体）、数据太少且有分布偏移。**
> **要把 pipeline 说成"OK"，最少先解决 P0 两项（真值测试集 + 任务重排）。**
