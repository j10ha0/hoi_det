# 任务重新定义：视觉场景 → 抓握配置预测控制（EMG 仅作触发）

> 你的澄清：
> - **EMG 只做一件事**：检测「发力 / 静息」→ 触发/不触发
> - **视觉做实时预测控制**：
>   ① 手是否到达物体附近（未接近 → 不输出抓握）
>   ② 接近时**预测抓握形态**（物体 shape → 抓握形态的**映射需要学习**，不能硬编码）
>   ③ **预测腕旋方向**（例：掌心朝下但物体在手的右侧 → 虽已接触，仍需旋转才能抓）
> - **"我不是要做检测模型，我是要做视觉场景预测控制任务"**

---

## 一、确认：这个重新定义是对的

| | 旧理解（我之前写的）| **你的定义** |
|--|-------------------|-------------|
| 主线 | EMG 解码 + 视觉辅助融合 | **视觉预测抓握配置（控制）** |
| EMG 角色 | 主控制信号（融合同等地位）| **仅二值触发（门控）** |
| 视觉角色 | 提供 shape/contact 特征 | **场景→动作的规划器（主体）** |
| 任务性质 | 多模态分类 | **视觉策略学习（行为克隆）** |

**为什么这样更合理**：
- EMG 二值触发是这个任务里**唯一稳定可靠**的 EMG 用途（不需要它区分 5 种抓握）
- "什么物体 → 什么抓握"本来就是**几何/语义问题，视觉更擅长**
- 腕旋方向**只能**由视觉的"手-物相对位姿"决定，EMG 无法提供

**一句话**：**这不是融合问题，是"视觉当大脑、EMG 当扳机"的分工问题。**

---

## 二、任务的正式定义

### 输入
- **视觉**：头戴相机单帧（或短时序）
- （可选）手部关键点：MediaPipe 21 点 / 3D 手姿

### 输出（3 个头）
| 头 | 输出 | 类型 |
|----|------|------|
| **H1 接近** | 手是否到达物体附近 | 二值（门控：未接近则不动作）|
| **H2 抓握形态** | 球抓/力量抓/三指捏/侧捏/双指捏… | 5–6 类**分类** |
| **H3 腕旋** | 旋前 / 旋后 / 不需旋转（或连续角度）| 3 类 或 回归 |

### 触发（独立小模型）
- **EMG → 发力/静息**（二值）→ 决定是否执行 H2/H3 的预测

```
        ┌────────────────── 视觉规划支路（主体）──────────────────┐
图 像 ──►│ H1 接近? ──(否)──► 不输出                              │
        │      │(是)                                            │
        │      ├──► H2 抓握形态 (6类)                            │
        │      └──► H3 腕旋方向 (3类/角度)                       │
        └──────────────────────────────────────────────────────┘
                              │
        EMG ──► 发力/静息 (二值) ──► 门控 ──► 执行 / 不执行
```

**注意**：H1 未接近时**不输出抓握**是一个显式的**状态机**，不是纯分类 —— 这一点让任务更像控制而不是检测。

## 三、⭐ 关键问题：腕旋的标签从哪来？（必须先定）

这是新任务里**最大的未知**。四个选项：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. IMU 戴在手腕/手背** ⭐ | 直接测绝对姿态 → 腕旋角 | **最准、最直接**；还能顺手给手姿 | 需要硬件；需与视频同步 |
| **B. 3D 手姿估计**（HaMeR/WiLoR）| 从视频离线估计 3D 手部姿态 → 算腕旋 | 不加硬件 | 单目 3D 手姿**精度有限**、算法重；仍要另做标注 |
| **C. 解析专家**（PocketVLA 的做法）⭐ | 由「手位置+朝向 + 物体位置」**几何计算**出"需要旋转多少" | 无需人工标注，可大规模生成 | 是"规则答案"，学它 = 学规则（需注意别退化成拟合规则）|
| **D. 人工标注** | 人看视频标"该往哪旋" | 简单 | 慢、主观、量少 |

**我的建议**：
- **优先 A（IMU）**：既给腕旋标签，也给手姿真值 —— 一举两得；而且假肢实验本来就需要传感器
- **退而求其次 C（解析专家）**：像 PocketVLA 那样**先用规则生成监督信号**，快速验证"任务是否可学"
- **B 作为补充**：用于可视化与调试，不作为唯一标签源

## 四、⭐ 一个重要的实际推论：**视觉规划任务不依赖 EMG**

你说"还没有 EMG 和 vision 同步数据" —— 但按新定义：

> **H1/H2/H3 三个头全部只用视觉！EMG 只做触发。**

**推论**：
- ✅ **视觉规划支路现在就能开始做**，不需要等 EMG 数据
- ✅ 甚至可以先做**纯离线的桌面采集**（手机/相机 + 物体 + 手），先把"场景→抓握配置"学出来
- ✅ EMG 触发支路可以**并行独立开发**（它是简单二值任务），最后再拼上

**这解开了你的卡点**：不是"必须先有同步数据"，而是**两条支路可以分开推进**。

## 五、实验设计要改什么

### 5.1 必须采集的"场景多样性"（这是腕旋预测的前提）

| 维度 | 要覆盖的取值 | 为什么 |
|------|-------------|--------|
| **物体形状** | 5 种（球/柱/棱柱/带柄盒/薄片）| H2 的基础 |
| **手-物相对位置** ⭐ | 左/右/前/后/斜向 | **腕旋由相对位置决定** |
| **手掌朝向** ⭐ | 掌心向下/侧向/向上 | 同上 |
| **接近方向** | 从上方/侧面/正面接近 | H1/H3 的多样性 |
| 遮挡 | 部分遮挡场景 | 鲁棒性 + 防止捷径 |

> ⚠️ **如果只在一个固定位置、固定手掌朝向下采集，腕旋头根本学不到东西**（没有变化可学）。

### 5.2 标签清单（每次 trial 要记录）
```
trial 定义（实验设计给定）:
  · object_id / shape          → 但不直接给 H2 标签（H2 要学，不能硬编码）
  · 手-物相对位置 (left/right/front/...)
  · 初始掌心朝向 (down/side/up)
演示记录（需要测量）:
  · 实际抓握形态  ← 人工标注 或 由演示视频判定
  · 实际腕旋角/方向 ← IMU（首选）或 3D 手姿 或 解析专家
时序:
  · 接近时刻 t_reach（手进入物体附近）
  · 接触时刻 t_contact
  · EMG 发力 onset / offset
```

## 七、最小可行路径

```
Step 0  定标签来源（A/B/C/D 选一个）← 必须先定，否则采了数据也没法训
        建议：IMU 优先；没有就先走解析专家(C)验证任务可学性

Step 1  做一个"桌面离线采集"（不需要 EMG！）
        · 手机/相机固定（或头戴）
        · 5 种物体 × 多个相对位置/手掌朝向
        · 受试者自然抓取
        · 记录：视频 + (IMU 或 3D 手姿)

Step 2  训视觉规划支路（H1/H2/H3 三头）
        · 基线：ResNet18/ViT-Tiny 多任务头
        · 关键消融：不输入手姿 vs 输入手姿（腕旋预测是否需要显式几何）

Step 3  独立做 EMG 触发支路（二值发力/静息）
        · 1D TCN，指标：F1 / 误触发率 / onset 延迟

Step 4  拼接：EMG 触发 → 视觉规划 → 控制输出
        · 评价：任务成功率 + 时序指标（不是像素 F1）

Step 5  消融（论文核心）
        · 视觉 only / EMG only / 二者结合
        · 腕旋头：有它 vs 没有（抓取成功率差多少）← 这是你的亮点
```

## 八、需要你确认的三件事

1. **腕旋标签怎么来？**（IMU / 3D 手姿 / 解析专家 / 人工）← 决定 Step 0
2. **假肢硬件有腕旋自由度吗？**（若无，H3 的用途是"规划轨迹/重新定向"还是别的？）
3. **相机是头戴单目吗？** 单目图像对 3D 腕旋是**欠约束**的；
   若能用**深度相机**或**加手部关键点**，H3 会显著更可学。
