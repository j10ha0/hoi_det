## 一、我用的**不是模型** —— 是数据集自带的真值

我做腕旋/对准误差计算时，输入是 **EgoDex 自带的 4×4 姿态矩阵**：

```
observation.state.rightHand      (4×4)  ← 手部姿态真值
observation.state.rightForearm   (4×4)  ← 前臂姿态真值
observation.state.right{手指}Tip  (4×4)  ← 每个指尖
camera_intrinsics                (3×3)  ← 相机内参
```

**这些是 Apple Vision Pro 用 ARKit 在录制时直接追踪出来的真值**，不是我用模型估出来的。

**我的计算只是纯 numpy 向量运算**：
```python
R_rel = R_forearm.T @ R_hand      # 相对旋转
roll  = euler(R_rel)[0]           # 腕旋分量
ê     = wrap180(target_roll - roll)
```
**成本 ≈ 0**（几秒钟 CPU）。

**→ 所以我上一轮的实测结论是**：**"如果有真值姿态，标签就能造出来"** ——
**但"怎么拿到真值姿态"这个问题，我没有替你解决。**

## 二、⭐ 你自己采时，三条路（按精度/成本排序）

| 路线 | 姿态从哪来 | 精度 | 成本 | 需要模型? |
|------|-----------|------|------|----------|
| **A. 用假肢样机采** ⭐⭐ | **设备自己的腕关节编码器** | **精确** | 需要样机 | ❌ **完全不需要** |
| **B. 手背贴 ArUco** ⭐ | ArUco 解算 6D 位姿 | **高** | 一张打印纸 | ❌ 不需要 |
| **C. 公开手部姿态模型** | HaMeR / WiLoR / MediaPipe | ⚠️ **腕旋轴误差最大** | 几小时 GPU | ✅ 需要 |

### 关于路线 B：**你之前的遮挡顾虑，在这里不成立**

你上次质疑"手背标记会被挡" —— **那是针对"抓握瞬间"**。
但我们**训练用的窗口恰好是「接近窗口」（onset 前 90 帧）**，
那个阶段**手背是朝上/朝向相机的，标记清晰可见** ✅

**→ 只在接近窗口造标签 + 手背标记 = 可行且精确。**

### 关于路线 C：为什么"腕旋轴"是最糟的方向

**单目 3D 手部姿态估计的固有弱点**：
| 手部姿态分量 | 单目可观测性 |
|------------|-------------|
| 手指弯曲（在图像平面内）| ✅ 好 |
| 手在图像中的位置/方向 | ✅ 好 |
| **绕前臂长轴的旋转（旋前/旋后）** ⭐ | ❌ **最差**（这是"绕视线方向"的旋转，单目**欠约束**）|

**→ 而"腕旋"恰恰就是我们要的那个分量。这是单目方案的根本困难。**

**但有救**：
- **粗粒度（3 类方向）可能够用** —— 姿态估计误差 ~20–30° 时，只要真实 |ê| 较大（>30°），**符号仍大概率正确**
- **接近对准的帧**：符号会错，但那些帧本来就归入"已对准"类 → 影响有限
- **连续回归标签会被噪声污染** → 所以**建议先做 3 类，不要直接上回归**

## 三、⭐ 成本估算（"便宜与否"）

假设你自己采 **20–30 分钟视频 @30fps = 3.6万–5.4万帧**：

| 方案 | 一次性搭建 | 处理耗时 | 算力成本 | 精度 |
|------|-----------|---------|---------|------|
| **A. 假肢编码器** | 需要样机 | 实时记录 | ~0 | **最高** |
| **B. ArUco 标记** | 打印纸 + OpenCV（现成）| **几分钟**（CPU）| **~0** | **高** |
| **C. WiLoR**（3D 手部重建）| 装环境 ~半天 | 约 30–60 分钟 | 单卡 | 中（腕旋轴弱）|
| **C. HaMeR** | 装环境 ~半天 | 约 1–3 小时 | 单卡 | 中（腕旋轴弱）|
| **C. MediaPipe**（2D）| 已装好 | 约 15–30 分钟 | CPU 即可 | 低（无 3D）|

**结论**：
- **算力上都很便宜**（你有 4×TITAN V，几小时的事）
- **真正的成本是"精度"和"环境搭建"**，不是 GPU 时间
- ⭐ **路线 B（ArUco）在成本和精度上综合最优** —— 便宜、准、不需要装模型

## 四、⭐ 如果只能用公开模型：一个降低误差敏感度的技巧

**用「差分标签」代替「绝对误差标签」**：

| 标签形式 | 定义 | 对姿态误差的敏感度 |
|---------|------|------------------|
| 绝对误差 | ê = target − current | ❌ 强（绝对偏置直接进入标签）|
| **差分** ⭐ | Δ = roll(t+ΔT) − roll(t) （未来窗口内的实际旋转）| ✅ **弱**（固定偏置在差分中抵消）|

```
原始:  预测"还差多少度才对准"    → 需要绝对姿态，偏置有害
差分:  预测"接下来 0.5 秒会往哪转、转多少" → 偏置抵消，更鲁棒
```
**代价**：标签含义从"几何最优"变成"人会怎么做"（模仿），但对闭环控制同样有效。

## 五、⭐ 我建议的选择顺序

```
优先 1: 假肢样机 + 编码器     ← 有样机就用这个，最准最省
优先 2: 手背 ArUco（接近窗口） ← 没样机时最优，成本≈0
备选 3: WiLoR / HaMeR + 3类标签 + 差分    ← 完全不想碰硬件时
不用:   IMU（你不想要）、MediaPipe 2D（信息不足）
```

**还可以做的验证**：用**标记**在少数序列上跑一遍，作为**3D 手姿模型的"真值"去校验它的腕旋精度** —— 这样你能知道模型标签到底有多脏。
