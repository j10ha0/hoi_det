# 指标定义与注意事项（务必先读）

> 回答：「0.7832 是什么指标？」
> **它是二值「手 vs 背景」像素级 F1（左右手合并）—— 一个偏宽松的指标，单独用它汇报会误导。**

---

## 1. 精确定义

训练脚本 `train_student.py::evaluate()` 里 `"hand"` 这一项的计算：

```python
gt   = (y_hand != 0)          # 左手(1) 或 右手(2) 都算「手」
pred = out["hand"].argmax(1) != 0
# 在【整个验证集所有帧所有像素】上累计 TP/FP/FN，再算
F1  = 2·P·R/(P+R)
```

即：**像素级、二值、左右手合并、全局累计（不是按帧平均）**。

### 用它读出的完整数字（最佳模型 `runs_v5/C4_l0.5/best.pt`）

| 指标 | 值 |
|------|-----|
| **hand F1** | **0.7832** |
| hand IoU（二值）| 0.6437 |
| Precision | 0.8793 |
| Recall | 0.7061 |
| 像素计数 | TP=996,670 / FP=136,864 / FN=414,902 / TN=14,507,884 |

---

## 2. ⚠️ 它**不是**什么

| 常见误解 | 实际 |
|---------|------|
| ❌ 3 类 mIoU | 实际二值合并 → **不能**当分割质量总评 |
| ❌ 左右手分别的 F1 | 左右手被合并 |
| ❌ 帧级准确率 / 检测率 | 它是像素级 |
| ❌ mAP / 实例分割 | 完全不涉及实例 |
| ❌ 与 EgoHOS 教师可直接比 | 教师指标是 9 类 mIoU，**不可比** |

---

## 3. ⚠️⭐ 它**掩盖**的问题（同一模型实测）

拆成 3 类后的真实情况：

| 类别 | IoU | Precision | Recall | 真值像素 |
|------|-----|-----------|--------|---------|
| 背景 | 0.9634 | 0.9722 | 0.9907 | 1464.5 万 |
| **右手** | 0.5916 | 0.6634 | **0.8455** | 81.9 万 |
| **左手** | **0.1453** | 0.9628 | **0.1461** | 59.3 万 |

- **左手基本失败**：召回仅 **0.146**，且**36.7% 的左手像素被判成右手**（右手→左手误判为 0）
- **背景 IoU 0.963 是虚高**（背景占 95% 像素，随便全预测背景就有 0.95）
- 3 类总体像素准确率 0.9521 —— 同样被背景主导，**不是有意义的成绩**
- 3 类平均 IoU = (0.9634+0.1453+0.5916)/3 = **0.5668** ← 更诚实的数字

**为什么二值指标看不出来**：左手像素被预测成"右手"时，在二值（手 vs 背景）口径下**仍算 TP** → 左右混淆被完全隐藏。

---

## 4. 左手为什么失败（已查明原因）

| 划分 | 左手像素 | 右手像素 | 左右比 |
|------|---------|---------|--------|
| **train**（视频1）| 4,826,935 | 15,817,311 | **0.305** |
| **val**（视频2）| 10,885,900 | 15,037,788 | **0.724** |

两个叠加问题：
1. **类别不平衡**：训练集里左手只占手部像素的 23%（右手 77%）→ 模型偏向预测"右手"
2. **训练/验证分布偏移**：验证集来自**另一段视频**，左手占比（42%）远高于训练集（23%）

→ 这是"按视频划分"带来的**场景偏移**，不是纯粹的模型缺陷，但**必须解决**。

## 5. 其它值得注意的点

| 项 | 值 | 说明 |
|----|-----|------|
| 帧级完全漏检 | **0/320 (0%)** | 每帧都能检出"有手"，这项不错 |
| 预测手区域 8×8 块数 | 86.6 ± 17.7 | 偏多，说明预测区域**较碎**（可能碎片化/边缘毛糙） |
| 帧级覆盖 | 左手 129/320 帧，右手 320/320 帧 | 左手漏了很多帧 |

## 6. 建议（汇报与实验都要改）

### 汇报口径
必须同时给出三个数，否则误导：
```
① 二值「手 vs 背景」F1 / IoU      （当前 0.7832 / 0.6437）
② 3 类 mIoU（均值 + 每类）        （当前 0.5668；左手 0.145 需单独标出）
③ 每类 Precision / Recall
```
**不要**只报 ①，更不要把 ① 说成"分割精度"。

### 修左手
1. **类别加权**（对 left 类提高权重，或按类别频率反比加权 CE）
2. **按帧/场景平衡采样**（避免右手主导）
3. 若最终应用**不需要区分左右手** → 把主任务直接定义为二值"手"，并在报告中明确说明
4. **换划分方式**：按视频划分造成分布偏移 → 用多视频混合划分，或报告"跨场景"结果作为泛化指标

### 对已有结论的影响
EXP_001~005 的**相对比较**（辅助头、λ、教师层）都是在同一指标下做的，方向性结论仍成立；
但**绝对排名需要改用 3 类 mIoU 复核**（尤其左手差的配置可能被二值 F1 高估）。
