# 对准误差标签怎么造？—— 实测方案（不需要物体位姿）

> 你的问题：**"对准误差只需判别式视觉特征，我怎么标定？基于公开数据集（人手）标定离散的吗？比如逆时针 −1 / 顺时针 +1？"**
>
> **答案：可以离散（建议 3 类），但标签不是靠"逆时针/顺时针"人工定义，而是用「自监督代理」自动算出来 —— 而且只需要手部姿态，不需要物体位姿 → 公开数据（人手）可用！**

---

## 一、⭐ 核心：用「自监督代理」定义对准误差

### 关键洞察

```
对准误差的本质 = "距离最终抓握姿态还差多少腕旋"
             = 抓握时刻的腕旋角 − 当前腕旋角
```

**为什么这招好用**：
- 人在抓握时**最终一定会对准**（否则抓不住）
- 所以"最终抓握姿态"就是**天然的对准目标**
- **只需要手部姿态序列，不需要物体位姿！** ⭐
- → **EgoDex / HOI4D 这类只要手姿的公开数据都能用**

### 公式

```python
# 1) 逐帧算「手相对前臂」的旋转
R_rel = R_forearm.T @ R_hand
roll  = 腕旋分量（绕前臂长轴）

# 2) 找抓握起始时刻 onset（用指闭合度上升沿，已验证）
target_roll = median( roll[onset : onset+30] )    # 抓握后的稳定腕旋角

# 3) 每帧的标签
ê(t) = wrap180( target_roll − roll(t) )
```

## 二、⭐ 实测结果（EgoDex，7633 帧 / 26 episodes）

### 2.1 先确认"腕旋轴"

相对旋转的三个欧拉分量，抓握过程中累计变化：
```
roll(绕x)   累计变化 445.2   ← 最大 → 这就是腕旋轴 ✅
pitch(绕y)  累计变化 343.8
yaw(绕z)    累计变化 366.2
```
**→ 绕 x 的分量 = 腕旋（旋前/旋后）**

### 2.2 对准误差 ê 的分布
```
P1=−53°  P5=−36°  P25=−12°  P50=0.3°  P75=+14°  P95=+36°  P99=+53°

|ê| > 30° 的帧:  1390 (18.2%)
|ê| > 60° 的帧:    64 ( 0.8%)   ← 大偏差很少
```

### 2.3 ⭐ 三分类标签分布（阈值 ±15°）—— 按窗口对比

| 训练窗口 | 帧数 | 向+ | 向− | 已对准 |
|---------|------|-----|-----|--------|
| 全程（所有帧）| 7633 | 29.8% | 27.4% | 42.7% |
| **接近窗口（onset 前 90 帧）** ⭐ | 418 | **36.4%** | **26.3%** | **37.3%** |
| 接近+抓握 | 825 | 21.1% | 19.5% | 59.4% |

**→ 用「接近窗口」的帧训练，类别分布最平衡（36/26/37），而且这正是你 ALIGNING 状态需要的帧！**

而**对准误差全程是 30/27/43，接近窗口 36/26/37 → 完全可训** ✅

## 三、⭐ 所以：离散还是连续？

### 三种形式，都可以

| 形式 | 标签 | 用途 | 难度 |
|------|------|------|------|
| **离散 3 类** ⭐ 建议先做 | {向+旋转, 向−旋转, 已对准} | 直接驱动"转/不转" | 低 |
| 离散 2 类 + 阈值 | {向+, 向−} | bang-bang 控制 | 最低 |
| **连续回归** | ê（度，带符号）| **比例控制**（转得快慢随误差）| 中 |

**建议**：
```
先训【3 类分类】跑通 → 再升级【连续回归】做比例控制
（或两个头都出：分类给方向 + 回归给幅度，更稳）
```

⚠️ **注意：不是"逆时针/顺时针"**，而是"**需要向哪个方向旋转以对准物体**" ——
这个方向由 `ê` 的符号决定，**是算出来的，不是人工定的**。

## 四、⭐ 完整标注流程（可自动化，零人工）

```python
# 输入：一段自由抓取的视频 + 对应的手部姿态序列
# 输出：每帧的 { 抓握类型, 对准误差 } 标签

for seq in 所有序列:
    # 1) 算腕旋角序列
    roll = [腕旋角(手姿[t], 前臂姿态[t]) for t in seq]
    
    # 2) 用指闭合度找「抓握起始」onset
    closure = 手指闭合度(手姿[t])
    onset = 第一个"连续5帧闭合"的位置
    
    # 3) 抓握目标姿态
    target = median(roll[onset : onset+30])
    
    # 4) 只在「接近窗口」内打标签（onset 前 90 帧）
    for t in range(max(0,onset-90), onset+1):
        ê = wrap180(target - roll[t])
        label_dir = 0 if ê > +15 else (1 if ê < -15 else 2)
        # 5) 质量过滤（自动）
        if 手不可见(t) or 标记置信度低(t): 跳过
        保存 (图像[t], grasp_type, label_dir, ê)
```

**全程零人工标注**（除定义阈值）。

## 五、⚠️ 四个必须注意的坑

| # | 坑 | 处理 |
|---|-----|------|
| 1 | **大偏差帧很少**（|ê|>60° 只占 0.8%）| ⭐ **数据增强**（图像旋转/翻转模拟不同偏差）或**合成更大偏差** —— 否则模型学不到"严重不对准"的情况 |
| 2 | **捷径学习风险** | 抓握后的操作帧里"手拿着东西"的外观极易判别 → **必须排除抓握后的帧**（只用接近窗口）|
| 3 | **人手 → 假肢手域差异** | 公开数据预训练后，**用假肢样机采少量数据微调** |
| 4 | **球体例外** | 球体"对准"无定义 → 从对准任务中**排除**（只用于抓握类型）|

## 七、⭐ 直接回答你

### Q1："我怎么标定？"
**不需要人工标定** —— 用**自监督代理**自动算：
```
ê(t) = (抓握时刻的腕旋角) − (当前腕旋角)
```
**只需要手部姿态序列**，不需要物体位姿。

### Q2："基于公开数据集（人手）标定？"
✅ **可以！我已在 EgoDex 上实测成功**：
- 腕旋轴确认（roll 绕 x，抓握过程累计变化 445°）
- 标签分布可用（接近窗口 36/26/37，不是上次 H1 那种 94.6% 单类）
- **18.2% 的帧 |ê|>30°** → 模型能看到真实的"未对准"状态

### Q3："离散的吗？逆时针 −1 / 顺时针 +1？"
**可以离散，但**：
- 建议 **3 类**：{向+旋转, 向−旋转, **已对准**} —— 要有"已对准"这一类（否则控制器不知道何时停）
- **方向由 `ê` 的符号算出**，不是人工定义"逆时针/顺时针"（因为要相对物体方向）
- 后续可升级为**连续回归**（做比例控制，自然减速不过冲）
