# 掌心法向的 2D 投影问题：手掌背对相机怎么办？

> 你的问题：**基于头戴相机 ego 视角，建模出来的手部法向量是 2D 的 —— 如果手掌背对相机怎么办？**
>
> **答案：改用 3D。而且这不是"优化"，是"必需"** —— 因为在 ego 视角下，
> 掌心背对相机很可能是**常态**而不是例外。

---

## 一、问题确认：2D 投影在什么情况下失效

### 目前的实现

```python
n3 = cross(kp[9]-kp[0], kp[17]-kp[5])   # 掌心法向（3D，相机坐标系）✓ 正确
n2 = normalize([n3[0], n3[1]])          # ⚠️ 只取 x,y 分量 → 2D 投影
ang = angle(n2, u2)                     # 与"指向物体"的 2D 方向比较
```

### 失效条件

设 `|n_xy| = sqrt(n3_x² + n3_y²)`（法向在图像平面内的分量长度）：

| 掌心朝向 | `n3_z` | `|n_xy|` | 2D 投影 |
|---------|--------|---------|---------|
| **侧面朝相机** | ≈0 | ≈1 | ✅ **可用** |
| **掌心正对相机** | ±1 | →0 | ❌ **退化**（投影趋零，方向由噪声决定）|
| **手背对相机（掌心背对）** | ∓1 | →0 | ❌ **退化**（同上）|

**关键**：当手掌穿过"正对/背对相机"的姿态时，`n2` 会**突然翻转 180°**
→ 算出的转角直接**反向**，闭环会往错方向转。

### 实测数据（EgoTactile）

```
|n_xy| 分布: 中位 0.99   <0.5 的比例 0%   >0.75 的比例 96%
```

**说明 EgoTactile 恰好都是"侧向抓握"**（掌心朝左右），所以 2D 投影碰巧能用。
但这是**数据集特性，不是普适保证**。

---

## 二、⭐ 根本解法：全程用 3D

**关键认识**：`n3` 本来就已经是 3D 的、且**在任何朝向下都有效** ——
问题只出在我把它**投影到 2D** 这一步。所以解法就是**不投影**。

### 正确的 3D 公式

```python
# ① 手：WiLoR 给的都是 3D
n3 = cross(kp3d[9]-kp3d[0], kp3d[17]-kp3d[5]); n3 /= |n3|   # 掌心法向
f3 = normalize(kp3d[9] - kp3d[0])                            # 手的长轴
P  = pred_cam_t_full                                         # 手的 3D 位置（相机系）

# ② 物体：2D 像素 → 3D 位置（需要【深度】）
r = normalize(K⁻¹ @ [u, v, 1])          # 从相机出发指向物体的射线
d = f_x * W_real / w_pixels             # ⭐ 深度：用物体【已知真实宽度】+【框像素宽度】估
O = d * r                               # 物体 3D 位置

# ③ 指向物体的 3D 方向
u3 = normalize(O − P)

# ④ 对准误差（完全 3D，任何掌心朝向下都有效 ✓）
ang = arccos( clamp(n3 · u3, -1, 1) )

# ⑤ 绕手长轴需要转的角度（带符号）
n_perp = n3 − (n3·f3) f3 ;  u_perp = u3 − (u3·f3) f3
θ = atan2( dot(cross(n_perp, u_perp), f3), dot(n_perp, u_perp) )
# sign(θ) = 往哪转；|θ| = 转多少

# ⑥ 单自由度腕旋做不到的部分
residual = ang − |θ|
```

**区别只在 ③④⑤ 用 3D 向量，不经过 2D 投影** → "掌心背对相机"不再是问题。

---

## 三、唯一的新依赖：物体的**深度**

3D 方案需要物体 3D 位置，而单目图像没有深度。四种获取方式（按推荐序）：

| # | 方法 | 精度 | 适用 |
|---|------|------|------|
| **1** ⭐ | **已知真实尺寸 + 框像素宽度**：`d = f_x · W_real / w_px` | 中高 | **你的实验物体尺寸可测** → 最实用 |
| 2 | **类别查表给尺寸**：`apple → 0.08 m`，`bottle → 0.065 m` | 中 | 需要检测器类别正确 |
| 3 | **假设物体与手同深度**：`d = P_z` | 低 | 粗糙近似，但方向误差可控 |
| 4 | **单目深度模型**（Depth Anything / Metric3D）| 高 | 多一个模型，但最通用 |
| 5 | **RGB-D 相机**（RealSense 等）| 最高 | 需要换硬件 |

**推荐 1**：你的 5 种设计物体，尺寸是已知的 → 一行代码就能估深度。

**注意**：深度误差对**方向**的影响是**有界**的（`u3` 是 `O−P` 的归一化，`d` 错 20% 时方向误差通常 <10°），所以中等精度就够。

---

## 四、如果一时拿不到深度：2D 方案的兜底

```python
nxy = hypot(n3[0], n3[1])      # 法向在图像平面内的分量
if nxy > 0.70:
    用 2D 方法（与原实现相同）           # 侧面朝相机 → 可靠
elif nxy < 0.40:
    # 掌心正对/背对相机 → 2D 不可用
    → 丢弃该帧，等下一帧                   # 你的场景是"非接触对准"，可以等
    → 或退化到 3D 近似（用同深度假设）
else:
    低置信度 → 时序平滑后再判
```

**好处**：在"非接触对准"阶段，手会持续运动 → **丢掉坏帧等好帧是可行的**。

## 五、⚠️ 一个更重要的推论

**在头戴 ego 视角下，"掌心背对相机"很可能是常态，不是例外**：

```
人伸手抓前方的物体（力量抓）
   → 掌心朝【前方/物体】，手背朝【后方/相机】
   → 相机看到的正是【手背】
   → n3 大致沿视线方向 → |n_xy| 小 → 2D 方案失效 ⚠️
```

**所以：**
| 结论 | |
|------|---|
| 2D 方案在 EgoTactile 上能用 | 只是因为它恰好都是侧向抓握 |
| **你的实际场景（头戴、正前方抓取）** | **大概率会遇到掌心背对相机** |
| **→ 3D 方案不是"优化"，是"必需"** | |

**这也解释了为什么之前的符号标定在 EgoTactile 上能给出 94° 的清晰差距，
但在别的数据上可能就乱了** —— 因为 2D 投影本身是脆弱的。

## 六、顺带修正一个此前的隐患

**WiLoR 的 `pred_keypoints_2d` 与 `pred_keypoints_3d` 不要混用**：
- `pred_keypoints_2d` 是**投影后的像素坐标**（受焦距假设影响，之前发现焦距差了 51 倍）
- `pred_keypoints_3d` 是**相机坐标系的真 3D 点** ✓

**新方案应全部基于 `pred_keypoints_3d`**，只在**画图**时才投影到像素。

## 七、一句话回答你

> **2D 投影在"掌心正对/背对相机"时确实会退化**（投影趋零 → 方向由噪声决定 → 转角可能反向）。
>
> **解法：全程用 3D。**
> `n3`（掌心法向）本来就是 3D 且任何朝向下都有效，问题只出在"投影到 2D"这一步。
> 只要把「指向物体的方向」也做成 3D（`u3`），比较就永远成立。
>
> **唯一新依赖是物体的深度** —— 用**已知真实尺寸 + 框像素宽度**估计即可（`d = f_x·W_real/w_px`），
> 你的实验物体尺寸可测，一行代码搞定；深度误差对方向的影响有界，中等精度足够。
>
> **而且这不是可选优化**：头戴 ego 视角正视前方抓取时，**相机看到的多半是手背** → 掌心背对相机是常态。
