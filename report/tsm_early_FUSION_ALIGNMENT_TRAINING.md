# 视觉 + IMU + EMG 融合：对齐与训练指南

> 条件：EMG **6 通道 @2000 Hz**（手臂）/ IMU / 头戴式视觉
> 核心问题：**如何对齐？如何训练？怎么知道融合真的有效？**
> 目录：`/mnt/storage/siat_cjh/proj/tsm_visual/`　日期：2026-09-15

## 0. 先看清"融合失效"的三个原因（对症下药）

| 失效模式 | 表现 | 根因 |
|---------|------|------|
| **① 视觉被忽略** | 去掉视觉，精度几乎不变 | **场景没信息**（物体↔动作一一对应）|
| **② 视觉主导** | 去掉 EMG 几乎不掉 | 视觉太强 + EMG 特征弱/被淹没 |
| **③ 信息冗余** | 融合 ≈ 任一单模态 | 两个模态在"回答同一个问题"，没有互补 |

**你要做的所有设计，本质上都是在防这三件事。**

## 1. 对齐：分三层，别只想着"时间戳"

### 1.1 时间对齐（硬件级，必做）
```
MCU 产生 1 Hz 方波 ──┬──→ EMG 采集系统的 AUX/Trigger 通道
                     ├──→ IMU 的 trigger 输入（若有）
                     └──→ 视野内 LED（被头戴相机拍到）
```
- 事后用「LED 亮灭帧 ↔ AUX 上升沿」互相关求时钟偏移
- **目标：报告同步残差（ms）**——这是你的方法学贡献（相关论文普遍不报）

### 1.2 时间尺度对齐（多速率融合）
| 模态 | 频率 | 融合时的处理 |
|------|------|-------------|
| EMG | **2000 Hz** | 主时间轴；窗口 **320 ms（640 点）**，步长 32 ms |
| IMU | 100–200 Hz | 线性插值到 EMG 栅格 |
| 视觉 | 30 fps（抽帧 2–5 Hz）| **不做逐帧对齐**：缓存为"当前场景上下文"，EMG 每窗口用最新场景 |

**关键认知**：**不需要把视觉硬拉成 2 kHz**。视觉本来就慢，把它当作"变化的上下文"，EMG 每步查询即可——这正是 `scene_conditioned_emg.py` 的做法。

### 1.3 语义对齐（最容易被忽略、也最决定成败）
> **两个模态不需要"特征空间对齐"，而要在"回答不同问题"上互补。**

| 模态 | 它回答的问题 | 输出什么 |
|------|------------|---------|
| **视觉**（头戴）| "看得到什么？" → 物体 / 操作场景 / 抓握 affordance | **场景嵌入**（每 200–500 ms 更新）|
| **EMG** | "肌肉在干什么？" → 动作 / 发力 / 时机 | **逐帧动作/关节角** |
| **IMU** | "手臂朝哪、动多快？" → 姿态 / 运动学上下文 | **运动嵌入**（与 EMG 同栅格插值）|

- 视觉/IMU 是**条件（condition）**，EMG 是**被条件化的主干**
- 这样即使两者的"语义"不同，融合也是**加法**而不是**冲突**

## 2. 训练：让融合有效的四个机制

### 机制① 让每个模态"有信息"（数据设计层面，最重要）
| 设计 | 做法 |
|------|------|
| 物体 ↔ 动作**多对多** | 每个物体 ≥2 种抓握；每个动作 ≥3 个物体 |
| 场景**随机化** | 物体位置/朝向随机；光照/背景至少各变 1 次 |
| 手臂姿态变化（对 IMU/EMG）| 不同手臂朝向/高度下重复同一动作 |
| **物体先行** | 物体比伸手早 1–1.5 s 出现（视觉可提供提前量）|

### 机制② 模态 Dropout（防单模态依赖）
```python
# 训练时随机丢弃某个模态（概率 p_drop，如 0.15）
if random() < p_drop_vision:  scene_feat = None      # 模拟视觉失效
if random() < p_drop_imu:     imu_feat   = None      # 模拟 IMU 失效
if random() < p_drop_emg:     emg = zeros_like(emg)  # 模拟 EMG 失效
```
**作用**：强制每个分支都能"独立撑住"，从而在测试时真正互补。

### 机制③ 退化增强（模拟真实退化，逼出互补）
| 模态 | 注入的退化 |
|------|-----------|
| EMG | 幅值衰减（疲劳）/ 基线漂移 / 通道置零（电极脱落）/ 降 SNR |
| 视觉 | 遮挡 / 弱光 / 运动模糊 / 随机丢帧 |
| IMU | 漂移 / 噪声 / 丢帧 |

### 机制④ 辅助监督（给弱分支"语义锚"）
```
L = L_main(动作 / 关节角)                       # 主任务
  + λ1 · CE(场景物体分类)      ← 约束视觉分支（让它学到物体语义，而不是乱码）
  + λ2 · L_motion(IMU 辅助)    ← 可选
  + λ3 · L_temporal(时序平滑)
```
**为什么重要**：头戴视觉如果只当"无监督特征"，很可能学到"背景/光照"等捷径；加个物体分类辅助头能让它聚焦真正有用的场景语义。

## 3. ⭐ 最重要：先做"融合有效性验证"（低成本试错）

**在正式大规模采集前，用 2–3 人小数据先验证视觉到底有没有用。** 这是省下几个月白干的关键。

### 验证实验（1~2 天可完成）
```
采集: 2–3 人 × 6 动作 × 每动作 10 次（物体多对多，物体先行）
训练: ① EMG-only  ② EMG+IMU  ③ EMG+IMU+视觉
比较: 三者的准确率/关节角 MAE
判据:
   ✅ 视觉带来 +3pp 以上（或 MAE 显著下降）→ 场景设计有效，可放量
   ⚠️ 提升 0~3pp → 调整场景设计（物体更多样/更多歧义）再试
   ❌ 无提升 → 场景无信息 → 必须改设计，别急着大规模采集
```

### 如果没有提升，优先检查这三点
1. 物体↔动作是否一一对应？（→ 改成多对多）
2. 物体是否在伸手前出现？（→ 否则视觉无提前量）
3. 视觉输入是否被背景/光照主导？（→ 加辅助监督 + 裁剪物体区域）

## 4. 针对你的配置（6ch EMG@2kHz + IMU + 头戴视觉）

```
┌─ EMG 分支（主干，流式）─────────────────────────┐
│  6ch × 320ms 窗 → 因果 TCN → z_e(t)              │
│  + 可靠性 r_e（RMS / MDF / SNR）                 │
└──────────────────────────────────────────────────┘
                ↓ query
┌─ 视觉条件（头戴，低频 2–5 Hz）────────────────────┐
│  抽帧 → timm/DINOv2 → 场景嵌入 s(t)              │  ← 物体/场景语义
│  + 辅助头：物体分类（监督）                        │
└──────────────────────────────────────────────────┘
                ↓ key/value
┌─ IMU 条件（100–200 Hz，插值到 EMG 栅格）──────────┐
│  6 轴 → 小 MLP/TCN → 运动嵌入 m(t)                │  ← 手臂姿态
└──────────────────────────────────────────────────┘
                ↓
   cross-attention（EMG 查询 视觉+IMU）→ 融合特征
                ↓
   输出：动作类别 + 关节角 θ̂
   损失：L_main + λ1·场景分类 + λ2·时序平滑
   训练：模态 dropout + 退化增强
```

**规模**：EMG 分支 0.26M + 视觉 timm-tiny 5.5M + IMU 0.1M ≈ **6M**（可换 resnet18 再降）

## 5. 判断融合是否有效的三条硬指标（写进论文）

| 指标 | 怎么看 |
|------|--------|
| **① 消融差** | 去掉视觉掉多少？去掉 EMG 掉多少？**两边都掉**才算互补 |
| **② 分层稳定性** | 视觉退化时融合掉得最少；EMG 疲劳时融合掉得最少 |
| **③ 提前量** | 从"物体出现"到"首次正确预测"的时间，融合应显著提前 |

**反面警示**：如果"去掉视觉几乎不掉"或"去掉 EMG 几乎不掉"，说明那一路是摆设——**不要用平均精度掩盖**。

## 6. 落地顺序建议

| 步骤 | 内容 | 目的 |
|------|------|------|
| **1** | 搭同步链路（LED+AUX），验证残差 <10 ms | 对齐前提 |
| **2** | **2–3 人预实验**，跑 §3 的三模型对比 | **验证融合有效** |
| 3 | 若有效 → 定稿协议（物体清单/时序/退化条件）| 放量准备 |
| 4 | 正式采集 10–15 人 × 2 会话 | 主数据 |
| 5 | 训练 + 消融 + 分层评测 | 论文主结果 |

**核心建议：不要跳过第 2 步。** 融合有效性是个可早验证的假设，用 1–2 天验证它能省下几个月。
