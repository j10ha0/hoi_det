## 二、实测证据（不是文献推测）

### 2.1 DexYCB：确认是「摄影棚第三人称」

**官方**（[dex-ycb.github.io](https://dex-ycb.github.io/)）：
- CVPR 2021，NVIDIA；"Studio CAD Model" + "RealSense Calibration" → **摄影棚多相机布置**
- 每被试 tar.gz **12 GB**，总计 **119 GB**；10 名被试
- 许可 **CC BY-NC 4.0**（非商用）

**实测图像**：`640×480`（RealSense），会话只有 **74 帧**（我下载的这段）
```
dexycb_000000.jpg  640x480
dexycb_000035.jpg  640x480
dexycb_000070.jpg  640x480
```
**实测手部位置**：手中心 y = **0.28 / 0.71 / 0.78**（乱变，无规律）→ 第三人称特征

### 2.2 EgoDex：确认是「头戴第一视角」

**格式**（LeRobot，实测 `meta/info.json`）：
- 视频 **1920×1080 @ 30fps**，键名 `observation.images.camera`
- **每帧手/前臂 4×4 位姿矩阵**：`leftHand/rightHand`、`leftForearm/rightForearm`、
  **全部手指关节**（拇指/食指/中指/无名指/小指 × 掌骨/指节/中段/指尖）
- 另有 `camera`（相机位姿 4×4）+ **`camera_intrinsics`（内参 3×3）**
- 任务示例：`add_remove_lid`、`arrange_topple_dominoes`（桌面操作）
- 单 episode：视频 93 MB + parquet 36 MB

**实测手部位置**（MediaPipe 检测）：
```
egodex_t0.jpg  手占画面 1.9%  中心 y=0.90   ← 手在画面底部
egodex_t3.jpg  手占画面 1.9%  中心 y=0.85
egodex_t6.jpg  手占画面 0.7%  中心 y=0.65
egodex_t10.jpg 手占画面 2.6%  中心 y=0.80
```
→ **手始终出现在画面下半部** = 典型**头戴第一视角**特征（对比 DexYCB 的 y 乱变）

### 2.3 ⭐ 决定性验证：腕旋角能直接算出来（不需要 IMU）

我用 EgoDex 的 4×4 矩阵做了几何计算：

```python
Rrel = R_forearm[:3,:3].T @ R_hand[:3,:3]      # 手相对前臂
roll = atan2(Rrel[2,1], Rrel[1,1])             # 绕前臂长轴的旋转 = 腕旋
```

**结果（7633 帧）**：
```
前几帧: roll = -95.5°, -95.5°, -95.6°, -95.9°, -96.2°, -96.4°   (连续变化)
全序列: roll 范围 -159° ~ -25°   标准差 21.9°
```
→ **腕旋角在序列内显著变化，可直接作为监督标签** ✅
→ **不需要 IMU、不需要人工标注** —— 你之前的顾虑（"IMU 标注很麻烦"）**被彻底绕过**

## 三、⭐ HOI4D：可能才是最匹配的（还需实际下载）

**官方**（[hoi4d.github.io](https://hoi4d.github.io/)）：
- CVPR 2022，清华 + 北大
- **2.4M 第一人称 RGB-D 帧**，4000 序列，9 名被试，**800 个物体实例 / 16 类**，610 个室内房间
- **逐帧标注**：全景分割、运动分割、**3D 手部姿态**、**类别级物体位姿**、手部动作
- 另有**重建物体 mesh + 场景点云**
- 下载项分开：RGB 视频 / Depth / CAD 模型 / **标注** / **相机参数** / **手部姿态**
- **有百度网盘镜像**（提取码 7gfs）← 国内可下
- 许可 CC BY-NC 4.0

**为什么它比 EgoDex 更对口**：
| | EgoDex | **HOI4D** |
|--|--------|-----------|
| 第一人称 | ✅ | ✅ |
| 手部 3D 姿态 | ✅ | ✅ |
| **物体 6D 位姿** | ❌ **无** | ✅ **有** |
| **RGB-D** | ❌ 仅 RGB | ✅ RGB-D（深度！解决单目 3D 欠约束）|
| 物体类别 | 任务命名，无位姿 | **16 类 / 800 实例** |
| 国内下载 | HF（可）| **百度网盘** |

→ **HOI4D 同时有"头戴 RGB-D + 手姿 + 物体 6D 位姿"** → 可以算出
**"物体的可抓面法向"** 和 **"掌心法向"** → **直接得到解析的"目标腕旋角"**！
这正是你"物体 shape → 抓握形态 + 腕旋对准"任务**最理想的监督来源**。

**注意**：HOI4D 的相机是**头戴 RGB-D 设备**（不是手机），视角是第一人称桌面操作，
与你的"头戴手机/相机"接近但**不完全相同**（FOV、安装高度可能有差异）。

## 四、给你的建议（三条路，按性价比）

### 路线 1：**EgoDex 打底**（最快，立刻能做）
```
EgoDex 第一人称视频 + 手/前臂 4×4 姿态
   → 算腕旋角（已验证）
   → 训"头戴 RGB → 腕旋角"（行为克隆人的自然抓取）
```
- ✅ 视角完全匹配你的头戴方案
- ✅ 腕旋标签免费（已验证）
- ❌ 无物体位姿 → **无法算"目标腕旋角"，只能学"人会怎么转"**（模仿，而非规划）
- 适合：先跑通"视觉→腕旋"的可行性

### 路线 2：**HOI4D 打底**（最对口，建议优先评估）
```
HOI4D 第一人称 RGB-D + 手姿 + 物体 6D 位姿
   → 解析专家算「目标腕旋角」（对准物体可抓面）
   → 训"RGB(-D) → 抓握类型 + 目标腕旋角"（规划）
```
- ✅ 有物体位姿 → 能算**目标**（不是模仿，是规划）
- ✅ 有深度 → 解 3D 歧义
- ✅ 国内可下（百度网盘）
- ⚠️ 需先下载确认数据格式与可用性（我可代做）

### 路线 3：**DexYCB 只当"姿态标注库"**（辅助）
- 视角不符 → **不适合直接训你的视觉模型**
- 但它的 **MANO + 物体 6D 位姿** 可用于：预训练手部姿态估计、验证几何算法
- 我建议：**不作为主数据集**

## 五、我的明确回答

> **DexYCB 不是你想要的场景** —— 它是**摄影棚第三人称**（640×480、8 相机环绕、12GB/人），
> 而你要的是**头戴第一视角**。用它训出来的模型**迁移到你的头戴相机上会有明显视角域差异**。
>
> **但你问对了一个更重要的问题** —— 我顺手验证了：**腕旋标签不需要 IMU**，
> 只要数据里有**手部+前臂 3D 姿态**，就能纯几何算出来（EgoDex 实测：roll 跨度 −159°~−25°）。
>
> **真正对口的是**：
> - **EgoDex**（头戴第一视角 + 全手骨架，已验证可用，但**无物体位姿**）
> - **HOI4D**（头戴 RGB-D + 手姿 + **物体 6D 位姿**，最全面，有百度网盘）
