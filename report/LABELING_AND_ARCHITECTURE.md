# 自由采集怎么打标签 + 能不能复用现有检测模型？

> 你的问题：
> ① 不按固定 trial 采，就是**日常抓握对准场景视频**，怎么打标签？
> ② 是给每帧打「逆时针 / 顺时针偏差」和「对齐」吗？
> ③ 训练的模型**能不能在已有的物体检测和手检测基础上**做？

---

## 一、标签格式：你的理解**基本对**，三点细化

### 1.1 对的

| 你的理解 | 评价 |
|---------|------|
| **每帧**打标签 | ✅ 对（控制回路需要 10–15 Hz 的逐帧判断）|
| **3 类**：逆时针 / 顺时针 / 对齐 | ✅ 方向正确 |

### 1.2 三个要细化的点

| # | 细化 | 原因 |
|---|------|------|
| 1 | ⚠️ 方向应是**物理方向**（**旋前 / 旋后**），不是"图像里的逆时针/顺时针" | 图像方向会随头动而变；控制需要的是腕电机的物理转向 |
| 2 | ⚠️ **必须有"已对准"这一类**，并定阈值（如 ±15°）| 否则控制器不知何时停 |
| 3 | ⭐ **只在「接近窗口」打标签**（排除抓握后的帧）| 抓握后"手拿着东西"的外观极易判别 → 会造成**捷径学习** |

**所以标签是**：`{旋前, 旋后, 已对准}`，逐帧，且只用接近窗口的帧。

## 二、⭐ 打标签的三条路（按"是否需要手姿测量"排序）

### 路 A：**用假肢自己采 → 编码器给真值** ⭐⭐ 最准
```
假肢执行日常抓取（遥操作或佩戴）
   腕旋角 ← 假肢编码器（精确、无模型）
   物体位置 ← 已知摆放 / 检测
   → 几何算标签，误差为零
```
**→ 如果采集能用假肢自己做，"打标签"这个问题就彻底解决了。**

### 路 B：**手姿模型 → 自监督代理**（自由采集可行）
```
离线跑 HaMeR/WiLoR → 腕旋角序列
   → 找抓握 onset（手指闭合）
   → ê(t) = 抓握时刻腕旋角 − 当前腕旋角
```
⚠️ **弱点**：单目手姿在"腕旋轴"上误差最大（恰是我们要的分量）→
**只适合粗粒度 3 类**，连续角度会被噪声污染。

### 路 C：**2D 几何启发式 → 弱标签** ⭐ **最省，可能直接够用**

**这是你可能没想到的一条** —— 在你的场景下可能特别有效（见下节）。

## 三、⭐⭐ 关键洞察：2D 几何启发式在你的场景下**可能是够用的**

### 为什么？

你的相机是**头戴俯视**、前臂大致**朝前（远离相机）**：
```
        相机（头顶）
           │  视线方向 ≈ 前臂长轴方向
           ▼
        手 ────► 物体
```
**→ 此时"旋前/旋后"（绕前臂长轴旋转）≈ 图像平面内的旋转！**

**所以从 2D 图像就能估计出腕旋方向**，不需要 3D：

```python
# 1) MediaPipe 拿到 21 个手部关键点（2D，免费、实时）
wrist, middle_mcp = lm[0], lm[9]
thumb_mcp, pinky_mcp = lm[2], lm[17]

# 2) 手的"指向"（图像内）
hand_dir = normalize(middle_mcp - wrist)

# 3) 掌面的"朝向"（图像内的翻滚线索）
#    拇指相对于 hand_dir 在哪一侧 → 指示掌心向哪
side = sign( cross(hand_dir, thumb_mcp - middle_mcp) )
palm_2d = hand_dir 旋转 ±90°（由 side 决定）

# 4) 期望方向：指向物体
u = normalize(obj_center - palm_center)

# 5) 图像内的对准误差
err = signed_angle(u, palm_2d)     # >0 / <0 → 三类
```

**→ 这套东西全部用现成模块（MediaPipe + 物体检测），不需要训练任何模型。**

### ⭐ 先做"纯几何基线"，可能不用训模型

**强烈建议先跑这个基线**，因为：
- 成本极低（一天就能搭起来）
- **如果它够用 → 你的问题就解决了，不用训模型**
- 如果不够用 → 它的输出可以当**特征**喂给网络，或当**弱标签**

## 四、⭐ 问题③：能不能在现有检测模型基础上做？—— **能，而且这是推荐做法**

### 三种架构

| 架构 | 说明 | 数据需求 | 评价 |
|------|------|---------|------|
| **1. 端到端单模型** | RGB → 分类头 | **高**（要学"找手找物"）| ❌ 你有少量数据，不划算 |
| **2. 两阶段** | 检测器 → 裁剪 → 分类 | 中 | 可行 |
| **3. 检测器 + 显式几何特征 + 小分类头** ⭐⭐ | 见下 | **最低** | **推荐** |

### ⭐ 架构 3 的具体形式（推荐）

```
┌─ 现成模块（不训练）────────────────────────────┐
│  MediaPipe Hands  → 21 个手部关键点             │
│  物体检测器        → 物体框 / 中心               │
└──────────────────┬─────────────────────────────┘
                   ▼ 计算【显式几何特征】（不用学）
   · hand_dir（手的指向）
   · palm_2d（掌面朝向，图像内）
   · u（手→物体方向）
   · signed_angle(u, palm_2d)          ← 几何对准误差
   · 手-物像素距离 / 相对尺度
   · 手部关键点本身（21×2）
   · 物体框尺寸 / 长宽比
                   ▼
┌─ 小分类头（要训练，很轻量）───────────────────┐
│  MLP / 小 CNN → { 抓握类型(5类), 对准方向(3类) }│
└──────────────────────────────────────────────┘
```

**为什么这套最适合你**：

| 优点 | 说明 |
|------|------|
| ✅ **数据需求极小** | 只有一个小 MLP 要学（几百~几千帧即可）|
| ✅ **复用成熟模型** | 手检测（MediaPipe）、物体检测（YOLO/RT-DETR）都是现成的 |
| ✅ **可解释** | 能分辨"是手检测错了"还是"对准算错了" |
| ✅ **可单独调试** | 每个模块可以独立验证 |
| ✅ **弱标签也能用** | 几何启发式的输出可当标签（先用路 C 启动）|

**唯一要注意**：物体检测器需要覆盖你的 5 种物体 →
- 先用通用检测器（YOLO 预训练 / GroundingDINO）零样本试
- 不够就自己标 200–500 张微调（很快）

## 五、⭐ 我建议的执行顺序（从最省到最强）

```
Step 0  纯几何基线（不训模型）
        MediaPipe 手 + 物体检测 → 算 2D 对准角 → 直接当控制器
        → 看它够不够用？          【1 天，成本最低】
             │
             ├─ 够用 → 完成！（可选：再训个模型提升鲁棒性）
             │

        用真正 3D 几何标签重训
                    ↓
Step 3  端到端微调（可选，最后才做）
```

## 六、⭐ 直接回答你的两个问题

### Q1：自由采集怎么打标签？是每帧打「逆时针/顺时针/对齐」吗？

**格式你说对了**：逐帧、3 类（含"已对准"）。三点细化：
- 用**物理方向**（旋前/旋后），不是图像里的顺逆时针
- **只在接近窗口**打标签（排除抓握后，防捷径）
- 阈值要定（如 ±15°）

**打标签有三条路**：
| 路 | 需要什么 | 精度 |
|---|---------|------|
| A. **用假肢自己采** | 编码器 | **精确**（推荐）|
| B. 手姿模型 + 自监督代理 | HaMeR/WiLoR | 中（腕旋轴弱）|
| C. **2D 几何启发式** | MediaPipe + 物体检测 | 弱但**可能够用** ⭐ |

### Q2：能在已有物体检测 + 手检测基础上训吗？

✅ **能，而且这是最推荐的做法**：
```
现成检测器（手 + 物体）
   + 显式几何特征（手朝向、手-物方向、夹角…）
   + 小分类头（只要训练这个）
```
**数据需求最小、可解释、可单独调试**，最适合你"自己采少量数据"的情况。

**而且更省的一步**：**先做纯几何基线，可能根本不用训模型。**
