# 视觉预测模型怎么训：输入形式 + 训练方案 + 公开工作

> 问题：这个视觉预测模型如何训练？数据是单帧图像吗？有公开方案吗？

---

## 一、⭐ 先回答"单帧够不够"——**三个头答案不同**

| 头 | 单帧够吗 | 原因 | 建议输入 |
|----|---------|------|---------|
| **H1 接近**（手是否到物体附近）| 🔶 **部分够** | 单帧能给"空间距离"，但**"正在接近 vs 正在离开"需要时序** | 单帧 + **滞回状态机**（或 2–3 帧）|
| **H2 抓握形态**（5–6 类）| ✅ **基本够** | 物体形状 + 手部形态在一帧内可见 | **单帧** |
| **H3 腕旋方向**（旋前/旋后）| ❌ **不够** | **掌心法向在单目 2D 图像里不可直接观测**（深度歧义）| 单帧 + **手部关键点/3D 姿态/深度** |

### 关键认知：H3 不是"感知"，是"规划"

腕旋方向**不由当前图像唯一决定**，而由**目标**决定 —— "让掌心朝向物体的可抓面"。
所以它是 **scene → action** 的映射（更多是策略问题），单目单帧是**欠约束**的。

→ **必须至少给模型手部几何信息**（关键点/3D/深度），否则 H3 学不出来。

---

## 二、推荐的输入形式（三档，按复杂度递增）

| 档 | 输入 | 适合 | 说明 |
|----|------|------|------|
| **档 1（最小基线）** | 单帧 RGB 224×224 | H2 验证 | 最快跑通，H3 大概率学不好 |
| **档 2（推荐起步）** ⭐ | 单帧 RGB + **MediaPipe 21 关键点** | H1/H2/H3 | 关键点 → MLP → 与图像特征 concat；**显式给几何**，H3 才可能可学 |
| **档 3（进阶）** | 短时序 8–16 帧（CNN + GRU / 3D CNN）| 提升 H1 平滑性、H3 靠运动视差 | 复杂；建议作为消融（"加时序有无增益"本身就是结果）|

**我的建议**：**从档 2 开始** —— 单帧 + 关键点是这个任务的"最小充分输入"；
档 3 留作消融实验。

## 三、训练方案

### 3.1 架构（多任务单模型）

```python
# 档 2 架构示意
img (B,3,224,224) ──► ResNet18 / EfficientNet-B0 / ViT-Tiny ──► f_img (B,512)
kpt (B,21,3)[可选] ──► MLP(63→128) ─────────────────────────► f_kpt (B,128)
                                                                │
                                      concat ──────────────────►│ (B,640)
                                                                ▼
                                            ┌───────────┬────────────┬───────────┐
                                            ▼           ▼            ▼
                                        H1 接近      H2 抓握形态    H3 腕旋
                                        (2–3 类)     (5–6 类)      (3 类 / 回归)
```

**可选增强（对应 PocketVLA 的 action-query）**：
加一个**门控嵌入**（把 EMG 的发力/静息作为 1 维输入或 gate），但**先不加**，让它纯粹是视觉模型。

### 3.2 损失

```python
L = λ1·CE(H1, 接近标签)          # 或 BCE（二值）
  + λ2·CE(H2, 抓握形态标签, weight=类别权重)   # 类别不平衡要用
  + λ3·L_H3(H3, 腕旋标签)         # 3 类→CE；连续角→SmoothL1
```
- **类别权重**：H2 若某些抓握类型样本少，必须加权（否则退化成只预测多数类，我们在 EXP_002 踩过这个坑）
- **H1 的标签定义要小心**："接近"要有个客观阈值（如手-物像素距离 / 物体框膨胀比例），不然标签不唯一

### 3.3 训练策略（关键：先预训练）

| 阶段 | 做什么 |
|------|--------|
| **① 预训练** | 用**公开手-物数据集**（见下文）预训练骨干 / 甚至预训练 H2 头 |
| **② 微调** | 用你自己的桌面收集数据微调三头 |
| **③ 防捷径** | **模态 dropout**：训练时随机把关键点输入置零（20–30%），避免模型只记几何规则 |
| **④ 时序后处理** | 滞回 + 最短保持时间（H1 尤其需要），**不用网络内时序**也能稳 |

## 四、⭐ 公开方案与相关工作（按"对你哪块有用"分类）

### A. 最对口的一类：**半自主假肢控制（视觉选抓握 + 用户触发）**

这类工作**就是你的架构**——视觉负责"抓什么/怎么抓"，用户用 EMG 触发：

- [Context-Aware Semiautonomous Control for Upper-Limb Prostheses](https://onlinelibrary.wiley.com/doi/10.1002/aisy.202501043)（*Advanced Intelligent Systems*）—— 上下文感知半自主控制
- [中文工作：视觉与肌电跨模态融合的假肢手动态调整实验](https://robot.sia.cn/cn/article/pdf/preview/10.13973/j.cnki.robot.240359.pdf)（《机器人》）—— 直接用**视觉 + 肌电融合**做假肢手控制，含截肢患者实验 ⭐ 强烈建议读

→ **这两篇是你论文最直接的参照与对手**，务必精读并做差异定位。

### B. 抓握类型识别（对 H2）

- [Precision and power grip detection in egocentric hand-object interaction using machine learning](http://www.recercat.cat/oai/request?verb=GetRecord&metadataPrefix=oai_dc&identifier=oai:www.recercat.cat:2117/394369) —— **第一人称**力量抓/精细抓二分类，与你 H2 同源
- [Fine-Grained Affordance Annotation for Egocentric Hand-Object Interaction Videos (WACV 2023)](https://www.openaccess.thecvf.com/content/WACV2023/html/Yu_Fine-Grained_Affordance_Annotation_for_Egocentric_Hand-Object_Interaction_Videos_WACV_2023_paper.html) —— 第一人称**可供性**细粒度标注
- 抓握分类学经典：**Cutkosky 抓握分类**（power / precision 家族）—— 你的 5 类抓握可映射到它，便于与文献对齐

### C. 抓握角度/姿态预测（对 H3 最接近的类比）

- [GG-CNN: Closing the Loop for Robotic Grasping — 实时生成式抓握合成](https://me336.ancorasir.com/wp-content/uploads/2023/06/Team8-Report.pdf)（原论文 Morrison et al., RSS 2018）
  - **单帧 RGB-D → 逐像素抓握质量 + 抓握角度**，实时
  - **这是与"H3 预测腕旋角"最接近的范式**：网络直接回归/分类抓握方向
- **GraspNet-1Billion**（Fang et al., CVPR 2020）、**AnyGrasp**（T-RO 2023）—— 6-DoF 抓握姿态预测（点云输入）
- **6-DOF GraspNet** —— 变分自编码器生成抓握姿态

### D. 手部 3D 姿态估计（给 H3 提供几何输入）

- **MediaPipe Hands** —— 2D 21 点，实时（你已验证可用）
- **HaMeR**（CVPR 2024）/ **WiLoR**（2024）—— 单图 3D 手部重建（较重，可离线做标注）
- **HandOccNet** —— 遮挡鲁棒

### E. 手-物交互公开数据集（预训练用）⭐

| 数据集 | 内容 | 可用来做什么 |
|--------|------|-------------|
| **DexYCB** | 手抓 **YCB 物体**，含手部姿态 | **你的 5 种形状可映射到 YCB 物体** → 直接预训练 H2 |
| **OakInk / OakInk2** | 手-物交互，抓握类型标注 | H2 预训练 |
| **GRAB** | 抓握分类学 + MANO 手姿 | H2/H3 语义 |
| **HO-3D / HOI4D** | 手-物 3D | H3 几何 |
| **HOT3D**（Meta）| 手-物 3D 追踪 | H3 |
| **EPIC-KITCHENS / Ego4D** | 第一人称，含抓握标注 | 第一人称域适配 |

> **建议**：用 **DexYCB 预训练 H2/H3 骨干**（它同时有手姿和物体），再到自己的数据上微调 —— 这能部分缓解你"数据不够"的问题。

### F. 行为克隆 / 策略学习框架（如果最终要做端到端）

- **ACT (Action Chunking Transformer)**（Zhao et al., RSS 2023）—— 模仿学习主流方案，预测动作块
- **Diffusion Policy**（Chi et al., RSS 2023）—— 扩散策略
- **PocketVLA**（你之前看的）—— 从零搭建的小 VLA，含 SFT + GRPO

## 五、我的最小可行训练方案

```
【数据】桌面离线采集（**不需要 EMG**）
   5 种物体 × 多种相对位置/掌心朝向 × 自然抓取
   每条样本: {单帧图像, (可选)手部关键点, H1接近标签, H2抓握类型标签, H3腕旋标签}

【模型】档 2：单帧 RGB + MediaPipe 关键点 → 三头多任务

【训练】
   1. 用 DexYCB/OakInk 预训练骨干（可选，但推荐）
   2. 自己数据微调，H2 加类别权重
   3. 训练时对关键点做 20–30% dropout（防捷径）

【后处理】H1 滞回 + 最短保持（不用网络内时序）

【消融（论文核心）】
   · 不用关键点 vs 用关键点        → **H3 到底需不需要显式几何？**
   · 单帧 vs 短时序               → 时序有没有增益
   · 有 H3 头 vs 无 H3 头          → **腕旋预测对抓取成功率贡献多少**
```

## 六、需要你确认

1. **H1「接近」的客观定义**是什么？（手-物像素距离阈值？物体框膨胀比例？）
2. 相机是**头戴单目**吗？若是，**强烈建议加手部关键点**，否则 H3 很难学
3. H3 标签来源（上一轮问的：IMU / 3D 手姿 / 解析专家 / 人工）—— 决定数据集怎么建
4. 5 种抓握类型能不能**映射到 Cutkosky 分类学或 YCB 物体**？能的话可以借公开数据集预训练

## 七、一句话总结

> **不必全部都用单帧**：H2 单帧够；H1 单帧 + 滞回状态机；**H3 必须给几何信息**（关键点/深度），否则单目单帧欠约束。
> **推荐起步：单帧 RGB + MediaPipe 关键点 → 三头多任务**；时序作为进阶消融。
> **公开方案最直接的对口是"半自主假肢控制"这一类**（视觉选抓握 + 用户触发），其中有一篇**视觉+肌电融合的中文假肢工作**必读；
> 抓握类型可借 **DexYCB/OakInk/GRAB** 预训练，抓握角度可参考 **GG-CNN** 范式。
