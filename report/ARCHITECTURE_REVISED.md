# 架构修订：EMG 为主 + 视觉为输入（V-E-A 的正确形态）

> 来自你的澄清：
> **输出 = 2 个 head**：① 机械手抓握方式 ② 静息 / 发力
> **视觉 = 输入模态**：提供 ① 物体 shape 感知 ② 接触状态感知
> 本文档评估这个设计，并指出必须提前处理的风险。

---

## 一、结论：这个修正是对的，它修掉了两个硬伤

| 原硬伤 | 新设计如何解决 |
|--------|---------------|
| ① **循环论证**（标签来自 EgoHOS，又用它评测）| ✅ **解决**：新标签是**真实的**——<br>· 抓握方式 ← 实验 trial 定义（球→球抓、柱→力量抓…）<br>· 静息/发力 ← EMG onset + 实验时序<br>**完全不再依赖 EgoHOS 伪标签** |
| ② **主任务选错**（手分割 ≠ 你要的）| ✅ **解决**：手分割不再是目标 → **左手 IoU 0.145 这个问题直接消失**（不评测了）|
| ③ 数据少 + 分布偏移 | ⚠️ 仍存在，但**危害变小**：标签来自你自己的实验，不再受 EPIC-Kitchens 场景偏移影响 |

## 二、修订后的架构

```
                    ┌─────────────────────────────────────────┐
   EMG (多通道) ───►│ EMG 编码器 (1D TCN)  → emg tokens        │
                    │                                          │
   视觉 ──────────► │ 视觉特征:                                 │
     · 物体 shape   │   · shape logits  (5 类)                 │
     · 接触状态     │   · contact logits (二值)    → vis tokens │
                    │                                          │
                    │        ▼ 融合 (共享 trunk / cross-attn)   │
                    │                                          │
                    │   ┌──────────────┬───────────────┐       │
                    │   │ Head-1       │ Head-2        │       │
                    │   │ 抓握方式(6类) │ 静息/发力(二值)│       │
                    │   └──────────────┴───────────────┘       │
                    └─────────────────────────────────────────┘
```

**对应 PocketVLA**：

| PocketVLA | 你这里 |
|-----------|--------|
| vision encoder | 视觉特征（shape + contact）|
| **language tokens** | **EMG tokens** ⭐ |
| action-query token | （可选）控制查询 token |
| shared trunk | 融合主干 |
| action head | **两个 head**（抓握方式 / 静息发力）|
| aux heads（深度监督）| vision 的两个感知头本身 |

**一句话**：**EMG 决定"何时/是否动"，视觉决定"怎么抓"** —— 分工清晰，比原来的设计合理得多。

## 三、⚠️⭐ 三个必须提前处理的风险

### 风险 ①：**捷径学习 —— 融合可能毫无增益**（最重要）

**问题**：如果 **shape 单独就能推出抓握方式**（球→球抓 是确定的映射），
模型会**直接学 shape→抓握**，完全忽略 EMG。最后你会发现"融合"没有贡献。

**同理**：如果 **EMG 单独就能判静息/发力**，Head-2 也不需要视觉。

**后果**：论文最核心的"多模态融合有效"这个结论**永远做不出来**。

**解法（关键在实验设计）**——必须构造**单模态不够**的样本：

| 困难场景 | 为什么需要融合 |
|---------|---------------|
| 物体在视野内但**不抓**（接触=0，EMG 有微弱预备活动）| EMG 易误触发 → 需视觉确认"没接触" |
| **抓握但物体被手遮挡** | 视觉失效 → 需 EMG 顶住 |
| **疲劳 / 不同力度** | EMG 幅值漂移 → 需视觉确认接触状态 |
| **靠近但未接触**（reach 阶段）| 只有视觉能区分"接近"与"接触" |
| 物体不在画面（超出视野）| 只有 EMG 可用 |

→ **实验协议里必须包含这些硬负样本**（这也是你之前定的"远距离手 30% + 靠近未接触 40% + 松开后 30%"）。

### 风险 ②：两个 head 可能互相矛盾

- 独立两个 head → 可能输出「静息 + 抓握方式=球抓」这种**不一致**组合
- **建议二选一**：
  - (a) **联合 6 类 head**：`{静息, 球抓, 柱抓, 柱体抓, 侧捏, 双指捏}` —— 简单、保证一致
  - (b) **门控 + 掩码损失**：Head-2 判静息/发力；Head-1 只在"发力"样本上学（masked loss），推理时若判静息则忽略 Head-1
- 我倾向 **(a) 先做基线**，再试 (b) 做对比（本身就是一个消融点）

### 风险 ③：指标必须换成**时序/控制指标**，不是像素 F1

现在（旧设计）用的 hand F1 / mIoU 在新架构里**统统不适用**。应该用：

| Head | 指标 |
|------|------|
| 抓握方式 | 分类准确率 / 混淆矩阵 / 每类 F1 |
| 静息·发力 | F1、**误触发率（false activation rate）**、**漏触发率** |
| **控制整体** | **onset 延迟**（从意图到输出，ms）、**稳定性**（抖动次数）|

其中 **onset 延迟**和**误触发率**才是假肢领域真正关心的数。

## 五、最小可行路径

```
Step 1  定义标签（真实标签，不依赖 EgoHOS）
         · 抓握方式: 由 trial 定义（物体→抓握映射）
         · 静息/发力: 由 EMG onset + 时序

Step 2  视觉侧产出 shape + contact
         选项 A: 用已训学生（shape/contact 头重训，权重加大）
         选项 B: 更轻——MediaPipe 握拳(已验证 d′=7.39) + 5 类形状分类器
         ⚠️ 先做选项 B 更容易建基线

Step 3  融合模型（先最简，再复杂）
         · 基线: late fusion（EMG 特征 ⊕ 视觉 one-hot → MLP → 2 heads）
         · 进阶: PocketVLA 式 token 融合（EMG tokens + vis tokens + action-query）

Step 4  ⭐ 消融实验（论文核心）
         · EMG only
         · EMG + shape
         · EMG + contact
         · EMG + shape + contact
         · 融合方式: late vs cross-attention vs token
         · 硬样本上的表现（遮挡 / 未接触 / 疲劳）
```

## 六、一个需要你确认的关键问题

**实验里"物体"是已知的吗？**

| 情况 | 含义 |
|------|------|
| **实验者指定物体**（受试者看到/拿起指定物体）| shape 在 trial 定义里**已知** → 用视觉推 shape 有"作弊"嫌疑，且模型会走捷径（风险①更严重）|
| **物体自由/不指定**（受试者自己选）| shape 必须由视觉推断 → 视觉价值真实，但要保证标签可获取 |

**我的建议（无论哪种情况）**：
> 实验里**故意加入视觉失效的场景**（遮挡、出画、暗光）和**EMG 模糊的场景**（预备但不动作、疲劳），
> 否则"融合有效"这个结论做不出来。

---

## 七、一句话总结

> **你的修订是对的**：EMG 主导 + 视觉提供 shape/contact → 双 head 输出抓握方式与静息发力。
> 它**修掉了循环论证和主任务选错**两个硬伤，但也意味着——
> **之前 5 个实验（手分割 + 蒸馏调参）降级为实现细节，真正的主体（EMG 分支 + 融合 + 双 head）还没开工**。
> 最该先做的不是继续调蒸馏，而是：**定义真实标签 → 搭最简融合基线 → 设计"单模态不够"的硬样本做消融**。
