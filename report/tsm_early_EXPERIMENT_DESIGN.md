## 0. 先想清楚一个决定性问题

> **场景条件要有用，采集时"场景"必须携带信息。**

如果你的数据里"每个物体只对应一种抓握"，那 EMG 自己就能学，**场景分支会被模型忽略**（学成摆设）。

所以采集设计有两条路线，**必须至少满足一条**：

| 路线 | 做法 | 场景带来的价值 |
|------|------|--------------|
| **A. 消歧**（推荐）| 同一 EMG 模式对应多种抓握 → 由场景决定是哪个 | 提升分类精度 |
| **B. 提前量** | 物体先出现，用户再动作 → 视觉提前预测 | 提升响应速度（earliness）|

**最佳做法：A+B 一起**（物体先出现 + 同一物体允许多种抓握）。

## 1. 任务定义

| 项 | 内容 |
|----|------|
| 输出 | **6 类动作**：握(power)、两指捏(pinch)、三指捏(tripod)、手指勾(hook)、手张开(open)、rest |
| 输入 | 前臂 sEMG（8–16ch @2kHz，流式）+ 场景帧（2–5 Hz）|
| 场景 | 桌面上的**物体**（决定"该抓什么/怎么抓"）|
| 真值 | **数据手套**（关节角）+ 提示时序（动作类别）|
| 应用 | 假肢/机械手控制（视觉给"抓什么"，EMG 给"何时/多大劲"）|

---

## 2. 采集设备

| 模态 | 设备 | 关键参数 |
|------|------|---------|
| **EMG** | 自研无线多通道 sEMG | 8–16ch，**≥1 kHz（推荐 2 kHz）**，带 AUX/Trigger 输入 |
| **视觉** | 头戴眼镜相机 或 固定 RGB 相机 | 1080p @30fps 全程录像（抽帧离线做，2–5 Hz）|
| **真值** | **数据手套**（已有）| 记录关节角 + 采样率 + SDK |
| **同步** | MCU（方波 + LED）| 一路进 EMG 的 AUX，一路驱动视野内 LED |
| **提示** | 显示器 + 音频 | 显示"物体图 + 动作名" |

## 3. ⭐ 场景设计（本实验的核心）

### 3.1 物体-动作矩阵（制造"多对多"）

| 物体 | 允许的抓握（≥2 种）| 说明 |
|------|------------------|------|
| 大圆柱杯 | **握** / **手指勾**（提把）| 同一物体两种抓握 → 造歧义 |
| 小圆柱瓶 | **握** / **两指捏** | |
| 小球（大/小）| **握** / **三指捏** / **两指捏** | 尺寸变化 → 抓握变化 |
| 笔 | **三指捏** / **两指捏** | |
| 钥匙 | **两指捏** / **三指捏** | |
| 提手/袋子 | **手指勾** | |
| 大平面物 | **手张开** | |
| （无物）| **rest** | |

**要求**：
- 每个物体**至少 2 种抓握方式**（打破"物体→动作"一一对应）
- 每个动作**至少在 3 个不同物体上出现**
- 物体**位置随机**、**朝向随机**

### 3.2 场景变化（提升鲁棒性 + 防捷径）

| 变量 | 水平 |
|------|------|
| 物体位置 | 随机（不要固定点位）|
| 光照 | 正常 / 偏暗（各采一部分）|
| 背景 | 至少换 1 次桌面/背景 |
| 遮挡 | 部分 trial 让手/物被挡（造视觉退化）|

### 3.3 trial 时序（关键：物体先出现）

```
[rest 2s]
→ [物体呈现 + 提示"如何抓" 1~1.5s]   ← 视觉先看到，可提前预测
→ [伸手 reach 1~2s]
→ [抓握保持 grasp 2~3s]
→ [松开 release]
→ [回 rest 2s]

★ 关键：物体必须在"伸手之前"就出现在视野中
   （否则视觉无法提供提前量，场景条件失效）
```

## 4. 采集协议

| 项 | 建议 |
|----|------|
| 被试 | **10–15 人**（健康，优势手）|
| 会话 | **2 次/人，间隔 ≥1 天**，重新佩戴电极/手套 |
| 组合数 | 物体 × 抓握方式 ≈ 8 物体 × 2 抓握 ≈ **16 组合** |
| 重复 | 每组合 **8–10 次** → 每人每会话 ≈ 128–160 trial |
| 休息 | 每 6–8 block 休 10s；每 30–45 min 长休 15 min |
| 熟悉化 | 正式前练习，**不纳入数据** |
| 问卷 | 性别/年龄/利手/前臂围度/健康史 |
| 伦理 | 知情同意 + 伦理审查 |

**规模估算**：12 人 × 2 会话 × 16 组合 × 9 次 ≈ **3456 trial**（足够训 6 类 + 消融）

## 6. 训练方案

### 6.1 数据划分（三种都报）
| 划分 | 训/测 | 证明 |
|------|-------|------|
| **LOSO** | 留 1 人 | 泛化（主指标）|
| **跨会话** | session1 训 / session2 测 | 抗电极漂移 |
| **新对象组合** | 留出未见的"物体×抓握"组合 | 场景泛化 |
| **跨场景**（光照/背景）| 正常训 / 暗光测 | 视觉鲁棒性 |

### 6.2 训练策略（关键：场景分支怎么训）
```
阶段1: 预训练场景分支（可选但推荐）
       场景编码器 + 分类头 → 预测"物体类别 / 抓握 affordance"
       （用物体清单做监督，让场景特征有语义）

阶段2: 联合训练
       L = CE(动作分类) + λ1·L1(关节角回归)
         + λ2·CE(场景物体分类)      ← 辅助任务，约束场景分支
         + λ3·L_temporal(平滑)

阶段3: 退化增强（逼出互补）
       EMG 侧: 幅值衰减/漂移/通道丢失（模拟疲劳）
       视觉侧: 遮挡/弱光/无场景（模拟视觉失效）
```

### 6.3 时间尺度对齐
- EMG：窗口 320 ms（640 点 @2kHz），步长 32 ms
- 场景：每 **200–500 ms** 更新一次（抽帧）
- 对齐：每个 EMG 窗口用"最近的场景帧"作为条件（`update_scene` 异步更新）

### 6.4 关键训练细节
| 点 | 做法 |
|----|------|
| 场景特征缓存 | 训练时同一 clip 内场景可视为常量；流式时按抽帧更新 |
| rest 帧处理 | 用 phase mask 排除，避免大量 rest 主导损失 |
| 类别不平衡 | 加权 CE 或降采样 rest |
| 防捷径 | 物体-动作多对多 + 位置随机 + 新组合测试 |
| 因果性 | EMG 分支因果卷积（已实现）；场景是"当前可用信息"，无因果问题 |

## 7. ⭐ 评测与消融（决定论文成败）

### 7.1 主结果（三基线 + 本模型）
| 模型 | 输入 |
|------|------|
| EMG-only | 仅 EMG 流式 |
| Scene-only | 仅场景帧 |
| 简单拼接融合 | 场景特征拼到 EMG |
| **本模型（场景条件）** | cross-attention 条件化 |

### 7.2 必做消融
| 消融 | 回答 |
|------|------|
| w/o 场景条件 | **视觉到底有没有用？** |
| 抽帧频率 0.5 / 1 / 2 / 5 Hz | 场景要多快更新 |
| 场景 backbone（tiny/resnet18/DINOv2）| 语义质量 vs 规模 |
| 退化条件（暗光/遮挡）| 鲁棒性 |

### 7.3 分层评测（核心卖点）
| 条件 | EMG-only | Scene-only | 融合 |
|------|----------|-----------|------|
| 正常 | ? | ? | ? |
| 视觉退化（暗光/遮挡）| 不变 | 掉 | **掉得最少** |
| EMG 退化（疲劳注入）| 掉 | 不变 | **掉得最少** |
| 新物体组合 | ? | ? | ? ← **场景泛化** |

再加**提前量曲线**：从"物体出现"到"首次正确预测"的时间（场景条件应显著提前）。

## 9. 最容易踩的坑

| 坑 | 后果 | 对策 |
|----|------|------|
| 物体→动作一一对应 | 场景分支学成摆设 | **多对多**矩阵 |
| 物体在伸手后才出现 | 无提前量，场景无法预测 | **物体先行 1~1.5s** |
| 场景固定不变 | 视觉无信息量 | 随机位置/朝向/光照 |
| 手套与 EMG 不同步 | 真值错位 | 同步误差先验证 |
| 只报平均精度 | 看不出场景价值 | **分层 + 消融** |
| rest 帧主导损失 | 模型全预测 rest | phase mask |
