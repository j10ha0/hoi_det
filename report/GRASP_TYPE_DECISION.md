# 抓握类型如何判断？—— 三种方案的比较与推荐

> 你的问题：**靠"检测出物体类别"判断，还是靠"掩码形状"判断？**
>
> **我的观点：两者都不是最优。应该"学"，而且标签可以从"人的实际手型"免费导出。**

---

## 一、三种方案的本质区别

| 方案 | 判据 | 输入依赖 | 泛化到新物体 |
|------|------|---------|-------------|
| **A. 类别查表** | 物体类别 → 预定义映射表 | 检测器的**类别** | ❌ **差**（表写死了）|
| **B. 掩码几何** | 掩码形状特征（长宽比/圆度/主轴）→ 规则 | **分割掩码** | 🔶 中（形状通用，但 2D 有歧义）|
| **C. 学习** ⭐ | 图像（+辅助特征）→ 抓握类型 | 只要图像 | ✅ **好** |

---

## 二、A 和 B 的问题（用我们实测的数据说话）

### 方案 A（类别查表）的问题

**① 类别检测本身就不准** —— 我们刚实测 COCO 检测器：
```
15 个物体里只有 6 个类别说对
Orange → sports ball   Carrot → baseball bat   Banana → kite
罐头/哑铃/夹子 → 检不出
```
**② 同一个物体，不同位姿抓法不同**
```
杯子正放 → 圆柱抓；杯子倒放 → 球抓；杯子躺倒 → 侧抓
→ 查表给不出这种区分
```
**③ 换个新物体就失效**（表里没有）

### 方案 B（掩码几何）的问题

**① 掩码本身不稳** —— 我们实测：
```
绿幕法定位率 90%，但 PCA 主轴一致率仅 78~81%
手遮挡时掩膜不完整（fill<0.5）→ 主轴判错
手臂残留被当成"细长物体"
```
**② 2D 轮廓看不出 3D 信息**
```
厚度、深度、结构（手柄）在 2D 掩码里看不到
带柄物体（要抓柄）→ 轮廓法做不到
```

## 三、⭐ 推荐方案 C：学习，且标签从"人的手型"导出

### 为什么标签能免费得到

**抓握类型的真值不在"物体类别"里，而在"人的实际手型"里**：

```python
# WiLoR / EgoDex / 数据集 都能给 21 个 3D 手部关键点
特征：
  · 各手指弯曲角   ∠(MCP, PIP, DIP)
  · 指尖到掌心距离比
  · 拇指-食指对合距离
  · 手掌宽度 / 手指张开度
        ↓ 聚类 或 映射到抓握分类学(Cutkosky: power/precision)
每帧一个【抓握类型标签】
        ↓
训「图像 → 抓握类型」
```

**这就是我们之前讨论的"自监督标签"思路** —— 而且它**同时绕开了两个坑**：
- ✅ 不依赖"类别检测准"（不用查表）
- ✅ 不依赖"掩码完整"（不用几何）

### 但类别仍然有用 —— 作为**条件/先验**，而不是唯一判据

```
抓握类型 = f( 图像特征 ,  物体类别 embedding )
              ↑兜底          ↑先验
```
- 类别判错 → 图像兜底
- 图像看不清（遮挡）→ 类别提供先验

**这比"查表"稳健得多**：查表是**硬依赖**，条件化是**软融合**。

## 四、⭐ 但有一个例外：你的实验里"物体→抓握"是设计好的

| 场景 | 建议 |
|------|------|
| **你的结构化实验**（5 种物体，物体→抓握有设计映射）| ✅ **查表可用** —— 而且它正好作为**baseline / 对照** |
| **泛化到任意物体**（真实假肢使用）| ✅ **必须用方案 C** |

**论文里可以两者都做**：
```
baseline : 类别查表（依赖检测器，简单）
ours     : 图像学习（泛化好，不依赖类别准确）
对比     : 说明"学习方案在检测出错/新物体时更鲁棒"
→ 这本身就是一个漂亮的消融
```

## 五、推荐的完整架构

```
┌─ 视觉支路 ──────────────────────────────────────────┐
│                                                      │
│  ① 手部: WiLoR → 掌心位置 + 掌心法向 n               │  ← 已验证可用
│  ② 物体: 检测器 → 框中心（+ 类别，作为辅助）           │  ← 用微调后的检测器
│  ③ 对准: u = normalize(p_obj − p_palm)               │  ← 几何，不用学
│           ang = angle(n, u)  →  腕旋指令              │
│                                                      │
│  ④ 抓握类型（H2）: 独立分类头                          │
│       输入 = 图像特征(骨干) ⊕ 物体框/掩码 ⊕ 类别embedding│
│       输出 = 5 类抓握                                 │
│       标签 = 由【手部关键点】导出的实际手型             │  ← 免费
└──────────────────────────────────────────────────────┘
        ↓
   EMG 门控（发力/静息）→ 执行
```

**关键解耦**（和我们上一轮定的原则一致）：
| 问题 | 用什么 |
|------|--------|
| **怎么对准？** | 物体中心 + 掌心法向（几何）|
| **抓什么？** | 学习的分类头（图像 + 类别先验）|
| **标签从哪来？** | **人的实际手型**（自动导出）|

## 六、一句话回答你

> **两种都不是最优**：
> - **靠类别查表** → 依赖检测器（实测只有 6/15 类别对），且同一物体不同位姿抓法不同，换个新物体就失效
> - **靠掩码几何** → 依赖分割（实测主轴一致率仅 78~81%），且 2D 轮廓看不出厚度/手柄
>
> **推荐：学一个分类头**，输入是「图像 + 物体框/掩码 + 类别 embedding」，
> **标签从"人的实际手型"（21 关键点 → 手指弯曲模式 → 抓握分类）自动导出** ——
> 这样**既绕开了类别不准，也绕开了掩码不稳**。
>
> **而你的结构化实验（5 物体设计映射）里，"类别查表"可以保留作为 baseline** ——
> 论文里对比"查表 vs 学习"，正好是一个有说服力的消融。
